# Code Accessibility Matrix — Public Verification Surface

> **Purpose:** Maps every layer a third party (auditor, regulator, institutional LP) can
> independently verify, and where operational secrets intentionally stay out of the repo.
> Nothing about the system's core mechanics is closed source.
>
> **Status:** Live · **Last updated:** September 2026

---

## 1. The honest framing

Noviscia runs a **two-repo topology**. The public verification surface is **this
repository**; the off-chain **alpha strategy engine** (searcher calculations, execution
venues, bot configs) lives in a separate private repository and is never part of the public
tree below. What both share: signing keys and provider credentials are **operational
secrets** that must never be committed — by design, not because anything is withheld.

The matrix below answers two questions for every layer:
**Is it independently verifiable?** and **If not, why not?**

## 3. Intentionally private (operational-secrets + alpha policy)

Two things are intentionally outside this repository. Each is structural, not accidental:

**The alpha strategy engine** lives in the private repo and is the only withheld *code*;
this repo's verification story does not depend on it (programs, invariants, and sandbox
stand alone). The remaining private items are **secrets**, each enforced by `.gitignore`:

| Secret | Path(s) | Why it stays out | Blast radius if leaked |
|---|---|---|---|
| Devnet searcher signing key | `.searcher-key.json` | the live keeper/executor signs with it | permanent loss of devnet operator key |
| Cold / hot key material | `.keys/`, keyceremony artifacts (`KEY_MANAGEMENT_GOVERNANCE.md`) | tiered custody; ceremony-grade separation | governance & treasury compromise |
| Environment secrets | `.env` (RPC creds, webhook/API tokens) | provider credentials, relayers | indexer/API abuse |

**Policy:** these files are git-ignored and never reach the repo. All proof artifacts that
reference them (measurement reports, runbooks) cite *paths and hashes*, never secrets.

## 4. Verification recipe for a skeptical reviewer

1. `git clone` the repository.
2. `cargo test -p noviscia-tvv-gate` — the invariant algebra's own unit tests.
3. `npm run chaos:invariant:baseline` — the independent parity replay (leakage must print `$0.00`).
4. Check every cited line in `docs/FORMAL_VERIFICATION.md` against the source.
5. Reassemble the `.so` and compare with the deployed program ID on devnet (`docs/DEVNET.md`).
6. Re-run the sandbox no-drain proofs (`docs/SANDBOX_HUB.md`).

Nothing on this list requires trusting Noviscia — every step is executable in this repo.
